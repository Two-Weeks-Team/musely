### 1.1 인프라 — Docker 단일 스택 (다음 단계 계획)
현재 프리뷰는 서버 없이 Cloudflare Workers로 정적 배포된다. 아래는 에이전트·멀티플레이를 붙일 때의 서버 구성 계획이다.

실행 위치를 **docker-compose 한 벌**로 통합한다. 우리 서버 밖의 의존은 둘뿐이다: Meta Model API 호출과 Muse Gadget SDK 브리지 (1.2).

```yaml
services:
  proxy:      # Caddy — HTTPS 종료, 정적 파일 서빙, /api·/ws 라우팅
  server:     # Node 이미지 1개: API 게이트웨이 + Colyseus 룸 서버 + 에이전트 코어 + 불지기 상주 프로세스
  negotiator: # 확장 사양용 프로파일 자리만 잡는다 — 제출 본선의 조율 격리는 server 프로세스 내 워커이며, 이 서비스는 컨테이너 승격 단계에서만 쓴다 (profile: session)
  muse-bridge: # 사용자별 Muse Gadget SDK 브리지 — 계정마다 페어링된 인스턴스를 격리 실행 (4.7)
  db:         # PostgreSQL 18 — 계정, 불씨 원장, 온도, 장소 레지스트리
```

- 로컬 개발·데모·운영이 전부 같은 명령이다: `docker compose up` 한 번으로 전체가 뜬다. 노트북에서 돌려 폰이 같은 네트워크로 붙는 구성이 데모의 기본형이다.
- 배포 경로는 둘, 이미지는 하나다:
  1. **전용 서버**: compose 그대로 실행. 앞에 Cloudflare를 DNS/CDN으로 붙인다 (터널 또는 오리진 연결).
  2. **Cloudflare Containers**: 2026-04 GA된 Cloudflare의 컨테이너 실행 환경으로, 같은 Docker 이미지를 그대로 올린다 【2550768784003796083†L48-L51】. 정적 웹은 Workers Static Assets 패턴과 조합 가능 【2550768784003796083†L400-L402】.
- 조율 세션의 격리는 제출 본선에서 server 프로세스 내 격리 워커가 담당하고(격리 수준 명시), 운영 단계에서는 negotiator 컨테이너(네트워크 차단·리소스 제한·세션 후 폐기)로 승격한다.
- Redis는 넣지 않는다: 단일 서버·방 단위 상태에서는 Colyseus 인메모리 상태 + Postgres 체크포인트로 충분하고, 구성 요소는 적을수록 좋다.

### 1.2 Muse 몰입 원칙 — 모든 층을 Muse로
이 프로젝트는 "Meta 기술을 몇 개 붙인 앱"이 아니라, 입력부터 폴백까지 전 층이 Muse 패밀리로 도는 것을 설계 원칙으로 삼는다.

| 층 | Muse 구성 요소 | 맡는 일 |
|---|---|---|
| 개인 에이전트 런타임 | Muse Spark 1.3 (Model API) | 각 Muse의 대화, 조율 후보 생성(공개 정보만), 비전 대조. 비공개 제약을 쓰는 수락 판정에는 쓰지 않는다 (4.3). Muse는 서버에 상주하는 에이전트다 — 주인 클라이언트 접속과 무관하게 동작하며, 비활성 Muse는 이벤트 기반으로 깨운다 (상시 전수 추론이 아니라 룸 이벤트·조율 수신 시 웨이크). 주인 연결 종료 시 런타임 인스턴스를 즉시 정지하고 위임 토큰을 전부 폐기한다 |
| 깊은 판단 | Muse Wonder 1.0 (Model API) | 장소 장기 기억 심의, 교착 조율 최종 조정, 분쟁·고액 검토 (Active Memory/Focus 활용) |
| 상시 경량 추론 | Muse Spark | 불지기 일상 응대, 피드 선별 1차 처리 — 경량 상시 추론도 Spark가 직접 담당한다 |
| 눈 | SAM 3.1 (Model API) | 물건·장소 특징 분리 (텍스트 프롬프트 기반 마스크/박스) |
| 얼굴 | Muse Image 1.0 (Model API) | 미연결 사용자의 초상, 문장 장식, 장소 스킨 텍스처 |
| 귀 | Muse Voice Transcribe 1.0 (Model API) | 음성 조건 입력 전사, 현장 확인 문구 전사 |
| 몸 | Muse Gadget SDK | 실제 Muse 아바타·투영을 가져오고 게임 사건을 본인 Muse·실물 가젯에 반영 (4.7) |
| 손 (제작) | Muse Code (+ 헤드리스 실행) | 구현·테스트·검증 자동화의 표준 작업 환경 |
| 도구 규격 | Museion MCP 서버 | 문장 검증·온도 조회·후보 제안·불씨 기록 도구를 한곳에서 정의, Model API 함수 호출과 Muse Code가 공유 |

- 파트너 인프라 선택: **없음.** Baseten·Fireworks·Modal 같은 외부 추론 파트너도, 오픈웨이트 자체 호스팅도 쓰지 않는다. 추론은 Meta Model API 하나로 해결하고, 조율 샌드박스는 Docker 컨테이너가 담당한다.
- 쓰지 않는 Muse 구성 요소도 명시한다: Muse Spark Open(816B)은 자체 호스팅에 약 700GB 가속기 메모리가 필요해 이 프로젝트 규모에 맞지 않는다. Wonder Full은 API가 아닌 Muse Code 구독 전용이라 런타임이 아닌 제작 층에서만 닿는다.

### 1.3 버전 핀 정책 — 최신 안정(GA)에 정확히 고정
모든 의존성은 "최신"이 아니라 **최신 안정 버전**에 정확히 핀 고정한다. 기준: GA(정식 출시)만 인정하고 RC·베타·프리뷰는 제외한다 (예: PostgreSQL 19는 RC 1 단계라 제외하고 18.6 계열 사용 【2237416388874878059†L53-L57】, GA 예정 2026-11-19 【2237416388874878059†L146-L147】).

- npm 패키지: `^`/`~` 범위 지정 금지, 정확한 버전 명시 + `package-lock.json` 커밋. AI 코딩 도구가 구식 API를 제안하는 문제도 핀이 1차 방어선이다.
- Docker 베이스 이미지: 정확한 태그 + 빌드 시점에 다이제스트(`@sha256:`)까지 고정.
- 모델 ID: 코드 상수로 핀 고정 (`muse-spark-1.3`, `muse-wonder-1.0`, `muse-image-1.0`, `muse-voice-transcribe-1.0`, `sam-3.1`). 모델 교체는 상수 변경 + 회귀 검증으로만.
- Gadget SDK: 릴리스 태그가 아닌 **커밋 해시로 핀** 고정하고, ESP-IDF는 SDK 요구대로 v6.0.1 정확히 고정.
- 업그레이드: 자동 갱신 금지. 올릴 때는 변경 이력 확인 → 샘플 재검증(설치·타입체크·빌드) → 핀 교체 PR, 이 순서만 허용.

렌더링 전략: 현재는 **WebGL2** 단일 경로다 — MapLibre 커스텀 레이어가 지도의 WebGL 컨텍스트를 공유해야 하기 때문이다. 아래 WebGPU 우선 전략은 10월 30일 계획 당시의 검토다. **WebGPU 우선 + WebGL2 자동 폴백.** WebGPU는 Safari 26(2025-09)부터 macOS/iOS 기본 탑재, Chrome 기본 탑재로 도달률이 약 85~87%까지 왔으나 WebGL(96%)에는 못 미치므로 단독 채택은 하지 않는다. Three.js WebGPURenderer의 자동 폴백이 이 구조를 그대로 제공한다.

## 4. 에이전트 코어

### 4.1 신원 (문장)
- 키 생성: WebCrypto Ed25519 키쌍을 기기에서 생성, 개인키는 기기 저장소(IndexedDB)에만 보관
- Agent Card: A2A 명세 형식(JSON)에 JWS 서명. 카드에는 공개 정보만 (이름, 성향, 기술, 권한 범위, 공개키)
- 문장 지문 렌더러: 공개키 해시를 시드로 절차적 문양(방사 대칭 패턴)을 캔버스에 그리는 결정적 렌더러 — 같은 키는 언제나 같은 문양. 검증은 상대 카드의 서명 검증 + 문양 재생성 대조
- 초상/장식: Muse Image 생성 이미지는 아바타와 카드 장식 전용 (검증 무관)

### 4.2 프레즌스와 만남
- 룸 = 모닥불 1개. server 컨테이너의 Colyseus 룸이 상태를 보유 (입장한 뮤즈, 좌석, 진행 중 세션). 룸 상태는 인메모리 + 주기적 Postgres 체크포인트
- 위치 전송 10Hz + 클라이언트 보간. 좌표는 geohash 셀 단위로만 서버에 전달, 정밀 좌표는 서버 저장 금지
- 인사 프로토콜: 입장 → 불지기(Spark 일상 응대 — 서명 검증은 결정적 코드가 수행하고, Wonder는 분쟁·교착 같은 깊은 판단으로 승격될 때만 호출) → 문장 확인 이벤트 → 좌석 배정

### 4.3 봉인 조율 엔진
- 상태 기계: `제안 → (수락/거부)×2 → 합의 | 조정(최대 5회) → 합의 불가` 를 명시적 상태 전이로 구현
- 세션 실행 위치 (제출 본선): server 프로세스 안의 세션별 격리 워커 — 세션 종료 시 폐기하고, 격리 수준이 컨테이너보다 낮음을 로그에 명시한다. 확장 사양에서는 server가 세션마다 기동하는 negotiator 컨테이너(외부 네트워크 차단, 내부망 전용, 리소스 제한)로 승격한다. 어느 쪽이든 세션에는 공개 정보와 후보, 수락/거부 신호만 들어간다
- 각 Muse의 수락 판정: 클라이언트 로컬에서 비공개 제약을 대조 (제약 원문은 기기 밖으로 나가지 않음). 판정 로직은 ① 규칙 기반 즉시 판정(시간·가격 범위) ② 규칙으로 판정할 수 없으면 주인에게 묻는 확인 큐, 2단 구성. 비공개 제약은 원격 Model API로도 보내지 않는다
- 후보 생성: 스파크 세션이 Muse Spark를 호출해 공개 신호 + 장소 맥락으로 후보 생성
- 세션 종료 시 후보·응답 로그 폐기, 합의문만 양쪽에 서명되어 저장

### 4.4 스파크 세션과 권한
- 권한 토큰: 두 카드의 권한 교집합을 계산해 서명된 세션 토큰 발급 (장소 셀 + 만료 시각 바인딩)
- 스파크 에이전트: 세션 동안만 존재하는 경량 에이전트. 도구 사용은 토큰 범위 내로 제한, 주인 확인이 필요한 행동(결제성 약속 등)은 UI 다이얼로그로 에스컬레이션

### 4.5 자율 행동 루프와 사건 (제출 범위 외 — 기획 서사와 규격으로 보존, PRD 절단 선언)
- 상주 런타임은 이벤트 기반 웨이크에 밤 생활 스케줄을 얹는다: 순회·공연·원정 같은 자율 행동은 세계 안에서 완결되는 행동 카탈로그에서만 선택되며, 각 행동은 원장 기록을 남긴다.
- 사건 생성: 밤마다 작은 사건(자리 다툼, 소문 전파와 왜곡, 약한 불, 방문자)을 시드 기반으로 발생시켜 관전의 변주를 만든다. 소문은 전파될 때마다 원장에서 변형 이력을 추적할 수 있어야 한다.
- 개성 상태: 말버릇·취향은 만남 기록에서 파생되는 경량 상태로 보관하고 대화 생성 시 주입한다. 아침 일기는 원장 이벤트를 내 뮤즈 중심으로 편집한 산출물이며, 주인 심지 확인 화면이 같은 데이터를 재사용한다.

### 4.6 불씨와 온도
- 만남 완료 시: 양쪽 Muse + 불지기가 합의문 해시에 다자 서명 → 불씨 레코드를 db(PostgreSQL) 원장에 기록
- 온도: 원장 레코드에서 파생 계산하는 서버 함수. 가중치 세부 수치는 서버 전용 상수로 비공개
- 신규 진입: 온도 하한은 고위험 과제의 중개에만 적용 (기획안 4.5 정책 그대로 코드화)

### 4.7 Muse Gadget SDK 브리지 — 실제 Muse를 데려오기
게임 속 Muse를 새로 만드는 것이 아니라, 사용자가 이미 가진 자기 Muse를 데려오는 경로다. vibeMuse에서 구조를 확인한 패턴(물리 장비용 SDK를 리눅스 서버가 가상 가젯으로 종단)을 따르되, 핵심 경로인 계정 페어링은 한 번도 실증된 적이 없다 — "남은 것은 실증뿐"이 아니라 경로 전체가 미실증이며, 그래서 M8은 본체와 독립으로 격리한다.

- 구조: 사용자 계정마다 `muse-bridge` 인스턴스 1개. Linux SDK(musegadget 서비스)를 컨테이너에서 실행해 그 사용자의 Muse와 페어링된 세션을 유지하고, 게임 서버와는 내부 API로만 통신한다. 웹 클라이언트는 SDK를 직접 만지지 않는다.
- 가져오기 (SDK → 게임): 사용자의 실제 Muse 아바타를 게임 아바타의 얼굴·표정 세트로 사용한다 (리그 캐릭터의 표정·외형에 반영). 연결하지 않은 사용자는 Jolly 기본형 또는 고른 10종 캐릭터를 그대로 쓴다 — 연결된 사용자에게 아바타는 "고른 캐릭터"가 아니라 "진짜 내 Muse"가 된다.
- 반영하기 (게임 → SDK): 게임 사건을 그 사용자의 Muse 쪽으로 되돌린다. 조율 요약·합의 결과는 `musegadget send-user-msg` 경로로 본인 Muse에게 전달되고, 물리 가젯(책상 위 기기)이 있으면 아바타 표정·상태가 게임 상태(불 앞에 앉음, 스파크 탄생, 불씨 수령)를 따라 바뀐다. 데모에서는 노트북·폰 화면 옆에 실물 가젯을 두는 구성이 된다.
- 동의·철회: vibeMuse meta_social의 동의/투영/철회(tombstone) 절차를 이 브리지의 권한 모델로 재사용한다. 투영 범위(아바타만/아바타+표정/조율 요약 수신 여부)를 사용자가 정하고, 철회하면 브리지는 즉시 분리되고 게임 아바타는 기본형으로 되돌아간다.
- 제약 (숨기지 않는다):
  1. 페어링은 계정마다 iOS/Android Muse 앱의 Developer mode 절차가 필요하다(최초 1회). 우회 경로는 없다 — 데모 계정은 사전에 페어링을 끝내 둔다.
  2. Gadget SDK는 개인·비상업 해커 프로젝트용으로 공개된 것이며 "지원되는 개발 플랫폼"이 아니다. 따라서 이 브리지는 데모와 개인 기기 채널로 위치시키고, 제품·상용 경로의 본체는 Model API로 유지한다(Startup 트랙 질의에서 이 경계를 먼저 말한다).
  3. 브리지 1인스턴스 = 1계정이다. 다중 사용자로 늘릴 때도 계정 간 토큰·세션 공유는 금지하고 인스턴스를 계정 수만큼 격리한다.

- **실제 모드 (정식)**: Geolocation API → 클라이언트에서 geohash 셀 변환 → 셀 단위 프레즌스. 불 자동 생성 3경로(제휴 등록/체크인 누적/소셜 밀도) 중 데모 범위에서는 제휴 등록 + 체크인 누적을 구현
- **데모 모드 (고정 시나리오)**: 무대 기본값은 Meta 본사 (1 Hacker Way, Menlo Park, CA — 좌표 37.48336, -122.15008) 주변으로 고정하고, 만남 장소는 본사 앞 카페로 둔다. 제작팀이 한국에 있어 위치는 실제 GPS가 아닌 가상 GPS(데모 모드 좌표 주입)로 대체한다. 오프닝 지도 연출: 초기 화면 범위는 실리콘밸리 전체(샌프란시스코–산호세 축, 약 20km 스케일)가 한 화면에 들어오는 뷰에서 시작해 본사 좌표로 끊김 없이 줌인해 지도 위 공원에 도착한다 (구현됨). 두 기기(노트북·폰)가 같은 룸에 접속하면 시나리오 스크립트(등장, 인사, 조율 주제)가 준비된 상태로 시작 (룸 접속은 미구현). 위치 판정은 시나리오 좌표로 대체하되, 나머지 전 경로(서명, 조율, 불씨)는 실제 코드와 동일하게 동작 — 데모 모드는 "위치 소스"만 바꾸는 토글이며 별도 데모 빌드를 만들지 않는다
- 폴백: GPS 권한 거부/실내 오차 시 수동 장소 선택 화면 제공

## 6. 멀티플레이/세션 흐름 (구현 단위)

1. 접속: 클라이언트 → proxy 경유 server 룸 WebSocket 연결, 카드 제시
2. 검증: 불지기 에이전트(Spark 상주 프로세스, server 내부)가 서명 검증·온도 조회 후 입장 승인 — 서명 검증 자체는 모델이 아니라 결정적 코드의 일이며, 모델 판단이 필요한 경우에만 Wonder로 승격한다
3. 프레즌스: 좌석·아바타 상태 동기화 (10Hz, 보간), 말풍선·이모트 이벤트
4. 과제 시작: 한쪽이 과제(만남 시간·장소 조율)를 제안 → 상대 수락 시 스파크 세션 생성 (격리 워커 기동 — 본선)
5. 조율: 4.3 상태 기계 구동, 진행 상황은 양쪽 화면에 "제안 카드 + 수락 표시"로만 표시 (이유 비공개 원칙을 UI로 강제)
6. 현장 확인: 폰 카메라 → SAM 3.1 분리 → Muse Spark 비전 대조 → 결과 표시 (보조 확인 고지 문구 포함)
7. 완료: 다자 서명 → 불씨 발급 애니메이션 → 원장 기록 → 세션 소멸

상대 없음/네트워크 단절 폴백: QR 코드로 같은 룸 직접 접속, 단절 시 로컬 캐시 시나리오로 영상 촬영 지속 가능.

## 7. Meta API 연동 (전부 실제 호출)

| 기능 | 모델 | 호출 위치 | 실패 시 폴백 |
|---|---|---|---|
| 조율 후보 생성(공개 정보만), 대화 | Muse Spark | 서버 게이트웨이 (키 보호) | 후보 생성 실패 시 규칙 기반 템플릿 후보로 강등하고 로그에 명시 |
| 불지기 상주 응대, 불티 피드 선별·요약, 경량 상시 추론 | Muse Spark | 서버 게이트웨이 | 재시도 큐 + 최소 정적 응대로 일시 강등, Model API 복구 시 자동 재개 |
| 불지기의 깊은 판단: 장소 장기 기억, 교착된 조율의 승격 심의, 분쟁 조정, 세션 요약 | Muse Wonder | 서버 게이트웨이 (저빈도 호출) | Wonder는 가벼운 모델이 아니라 Active Memory·Active Focus를 갖춘 고성능 에이전트 모델이다. 상시 호출이 아니라 "기억이 필요한 순간"에만 쓴다: 장소의 누적 맥락을 읽는 판단, Spark 조정으로 풀리지 않은 조율의 최종 심의, 고액 과제의 안전 검토 |
| Muse 초상, 문장 장식, 장소 스킨 텍스처 | Muse Image | 온보딩/장소 등록 시 1회 생성 후 캐시 | 절차 생성 플레이스홀더 (검증과 무관하므로 안전) |
| 물건 분리 | SAM 3.1 | 서버 게이트웨이 (이미지 업로드) | 사용자 수동 크롭 UI |
| 물건 대조 판정 | Muse Spark 비전 | 서버 게이트웨이 | "확인 불가"로 표시하고 사람 확인으로 진행 |
| 음성 입력 전사 | Muse Voice Transcribe (`muse-voice-transcribe-1.0`) | 실시간 WebSocket 전사 — ① 공개해도 되는 입력(조율 주제, 공개 희망 조건)을 말로 하면 전사된다. 비공개 조건은 원격 전사하지 않는다 — 기기에서 타이핑하거나 기기 내 전사로만 입력한다 ② 현장 만남에서 확인 문구를 말하면 전사 기록이 동의·본인 확인 로그가 된다 | 타이핑 입력으로 대체 |

- 호출 구조: 클라이언트는 Meta API를 직접 부르지 않는다. 전부 server 컨테이너의 게이트웨이를 경유한다 (API 키는 서버 환경변수에만 존재, 호출량 로깅·캐싱·폴백을 한곳에서 관리).
- 연동 규격 (베이스 URL과 SDK 호환성은 문서 확인 완료 — Voice Transcribe의 실시간 전사 형태와 SAM 3.1 출력 형식은 미확정이며 POC-1의 실응답으로 확정한다): Meta Model API는 `https://api.meta.ai/v1` 베이스에 OpenAI SDK 호환으로 붙는다 【6521326389744474683†L84-L86】. 별도 전용 SDK를 기다릴 필요 없이 TypeScript OpenAI SDK를 게이트웨이 어댑터로 고정하고, 모델 ID를 상수로 핀 고정한다: `muse-spark-1.3`, `muse-wonder-1.0`, `muse-image-1.0`, `muse-voice-transcribe-1.0`, `sam-3.1`. 조율 후보 같은 기계 판독 출력은 구조화 출력(JSON Schema)으로 받는다.
- 도구 호출 규격: 에이전트가 쓰는 도구(문장 검증, 온도 조회, 후보 제안, 불씨 기록)는 **Museion MCP 서버** 하나로 정의한다. Model API 쪽에서는 함수 호출로 연결하고, Muse Code는 MCP 클라이언트로 같은 도구를 쓴다 — 도구 정의가 한곳에서 관리된다.
- Muse Code의 위치: 구현·테스트의 제작 도구이자, 리포의 에이전트 작업 표준이다 (SDK 작업 지침 파일과 헤드리스 실행을 CI 성격의 검증에 사용).

백지에서 시작하지 않는다. 대회 규칙(신규 작업만 인정, 결과물 오픈소스 공개) 안에서 베이스 사용을 세 층으로 가른다.

- **자유 사용 (라이선스 표기만)**: 라이브러리와 엔진(Three.js, Colyseus, MapLibre GL 등), CC0·MIT·Apache 라이선스의 에셋 팩(로우폴리 모델은 Kenney CC0 팩 우선 검토). 사용 목록은 리포 README의 "기반 오픈소스" 절에 전수 기록한다.
- **조건부 사용 (골격만, 핵심은 신규)**: 스타터·보일러플레이트 코드는 골격으로만 쓴다. 차별 기능인 봉인 조율, 문장, Accord, 주인 심지, 스파크 위임은 전량 기간 내 신규 작성한다. 무엇을 기반으로 시작했고 무엇을 새로 만들었는지는 제출 README에 먼저 공시한다 — 심사위원이 발견하기 전에 밝히는 것이 원칙이다.
- **금지 (패턴 참조만)**: 본인 기존 프로젝트(vibeMuse 등)의 코드 재사용. "신규 작업만 인정" 조항과 충돌하므로 아키텍처와 패턴만 참조하고 코드는 새로 쓴다. 타 오픈소스 에이전트 시뮬레이션(AI Town 등)도 같은 원칙 — 구조 참조는 자유, 코드 차용은 라이선스를 확인한 뒤 항목별로 판단하고 공시한다.
- 지도 렌더링은 상용 지도 API 대신 MapLibre GL + OpenStreetMap 벡터 타일로 확정한다 — 비용과 약관 리스크가 없고, 다크 네온 스타일을 벡터 스타일 정의로 직접 만들 수 있다.
