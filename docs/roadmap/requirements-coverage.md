## 단계 전환의 역추적

- S1 P-07: P-01 전체 목록·P-02 진입·P-03 두 축/주인 개입·P-04 범위·P-05 장면·P-06 관측의 증거를 확인한다.
- S2: 모든 I 태스크는 P-07을 조상 선행 조건으로 가진다. I-03A는 transport만, I-03B는 모든 backend 연결 이후 전체 tool 검증이다.
- S3 D-01: I-02/I-03B/I-04/I-09/I-11/I-12와 그 조상들을 모두 포함한다. D-02/D-03/D-04가 실패하면 D-05/D-06은 ready가 아니다.
- S4: G-01은 개발 완료 뒤 일반 사용자 운영 분해/실행을 게이트로 관리하고 G-03이 파일럿 증거를 검증한다. G-02 directory는 I-04 후 병행하되 S3를 차단하지 않는다.

## 명시적으로 남은 외부/제품 checkpoint

- P-07의 제품 경험 확정은 화면 증거와 실제 검토 결과를 남겨야 한다. 단순 전달은 승인/완료가 아니다.
- I-02의 실제 웹캠·계정 권한, I-04의 본인 Muse 보안 자격/쓰기/예약 지원을 실제 계정에서 확인한다.
- D-04의 메모리 수용 예산과 대상 실기기는 시험 전에 결정한다. 아직 미정인 사실을 값으로 발명하지 않으며 미정이면 blocked다.
- G-01의 일반 사용자 정책/운영 하위 태스크, G-02의 외부 심사 기간은 후속 관찰로 구체화한다. 이것이 S1/S2 구현자가 제품 범위를 임의 결정할 권한을 뜻하지 않는다.
